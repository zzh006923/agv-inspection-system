# 数据库初始化与适配说明

## 一、模块概述

本项目数据库部分用于支撑 AGV 智能巡检系统的任务管理、缺陷记录、识别结果上传、传感器数据、车辆状态、系统配置等业务功能。

数据库脚本主要包括 MySQL 版本和 Kingbase 版本两类，用于在不同数据库环境下完成建表、初始化数据导入和真实小车接入相关字段扩展。

## 二、数据库脚本目录

数据库相关文件建议统一放在仓库的 `database/` 目录下：

```text
database/
├─ schema.sql
├─ schema-kingbase.sql
├─ data.sql
├─ data-kingbase.sql
└─ schema_update_real_car.sql
```

各文件作用如下：

| 文件名 | 作用 |
|---|---|
| `schema.sql` | MySQL 数据库建表脚本 |
| `schema-kingbase.sql` | Kingbase 数据库建表脚本 |
| `data.sql` | MySQL 初始化数据脚本 |
| `data-kingbase.sql` | Kingbase 初始化数据脚本 |
| `schema_update_real_car.sql` | 真实小车、传感器或硬件接入相关的补充表结构脚本 |

## 三、主要数据表说明

数据库表主要围绕 AGV 巡检业务设计，通常包括以下几类：

### 1. 巡检任务相关表

用于保存巡检任务的基础信息，例如任务名称、巡检区域、任务状态、创建时间和执行情况等。

主要支撑功能：

- 巡检任务创建；
- 巡检任务查询；
- 任务状态更新；
- 任务详情展示；
- 任务执行流程记录。

### 2. 缺陷记录相关表

用于保存巡检过程中识别或人工确认的缺陷信息。

主要支撑功能：

- 缺陷新增；
- 缺陷查询；
- 缺陷确认；
- 缺陷状态更新；
- 缺陷图片路径保存；
- 缺陷类型和描述记录。

### 3. 识别结果上传相关表

用于保存 YOLO 识别脚本上传的图片识别结果和相关元数据。

主要支撑功能：

- 识别图片路径保存；
- 识别结果保存；
- 置信度或识别类别保存；
- 上传时间记录；
- 与巡检任务或缺陷记录关联。

### 4. 传感器数据相关表

用于保存真实小车或传感器 Hub 上传的数据。

主要支撑功能：

- 温湿度数据记录；
- 光照数据记录；
- 烟雾检测数据记录；
- 人体检测数据记录；
- 传感器实时状态展示；
- IoT 概览页面数据支撑。

### 5. 车辆控制与状态相关表

用于记录 AGV 小车运动状态、心跳状态或控制动作。

主要支撑功能：

- 前进、后退、停止等控制动作记录；
- 小车在线状态判断；
- 任务执行过程中的车辆状态展示；
- 硬件联调过程数据记录。

### 6. 系统配置相关表

用于保存系统运行配置，例如接口地址、阈值参数、设备配置等。

主要支撑功能：

- 系统设置页面；
- 参数读取；
- 参数修改；
- 系统自检。

## 四、MySQL 初始化方式

如果使用 MySQL，可以按照以下顺序执行脚本：

```sql
source schema.sql;
source data.sql;
source schema_update_real_car.sql;
```

也可以在 MySQL 命令行中执行：

```bash
mysql -u root -p
```

进入数据库后：

```sql
CREATE DATABASE agv_inspection DEFAULT CHARACTER SET utf8mb4;
USE agv_inspection;

source 路径/schema.sql;
source 路径/data.sql;
source 路径/schema_update_real_car.sql;
```

如果使用图形化工具，也可以直接打开 SQL 文件并按顺序运行。

## 五、Kingbase 初始化方式

如果使用 Kingbase，需要优先执行 Kingbase 版本的建表和初始化脚本：

```sql
\i schema-kingbase.sql
\i data-kingbase.sql
\i schema_update_real_car.sql
```

如果使用 KStudio，可以将对应 SQL 文件导入后按顺序执行。

建议执行顺序为：

```text
1. schema-kingbase.sql
2. data-kingbase.sql
3. schema_update_real_car.sql
```

如果表已经存在，需要先确认是否需要删除旧表或只执行增量更新脚本，避免重复建表导致报错。

## 六、后端数据库配置说明

后端通过 Spring Boot 配置数据库连接。实际运行时需要根据本地环境修改数据库地址、用户名和密码。

建议开源仓库中不要直接提交真实密码，而是使用示例配置或环境变量形式，例如：

```yaml
spring:
  datasource:
    url: ${DB_URL:jdbc:mysql://localhost:3306/agv_inspection}
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD:123456}
```

Kingbase 示例：

```yaml
spring:
  datasource:
    url: ${DB_URL:jdbc:kingbase8://localhost:54321/agv_inspection}
    username: ${DB_USERNAME:system}
    password: ${DB_PASSWORD:123456}
```

实际部署时，应根据本机数据库端口、数据库名和账号密码进行调整。

## 七、数据库脚本开源注意事项

开源上传时应注意以下几点：

1. 可以上传建表脚本和示例初始化数据；
2. 不建议上传包含真实账号、真实密码、真实设备密钥的数据；
3. 不建议上传过大的运行日志、数据库备份文件或临时导出文件；
4. 如果 SQL 文件中包含测试数据，应确保不包含隐私信息；
5. MySQL 和 Kingbase 脚本应保持命名清晰，便于评审和队友查看；
6. 如果存在多个版本的 SQL，建议在文件名中体现数据库类型或用途。

## 八、常见问题

### 1. 执行 SQL 时提示表已存在

说明之前已经初始化过数据库。可以选择：

- 删除旧表后重新执行；
- 只执行补充字段或新增表的脚本；
- 新建一个干净数据库重新导入。

### 2. 后端启动时报数据库连接失败

常见原因包括：

- 数据库服务没有启动；
- 数据库端口写错；
- 数据库名不存在；
- 用户名或密码错误；
- MySQL / Kingbase 驱动配置不正确。

### 3. 前端页面没有数据显示

需要检查：

- 后端服务是否启动；
- 数据库是否成功初始化；
- 表中是否有初始化数据；
- 前端请求地址是否指向正确后端端口；
- 后端接口是否能够正常返回数据。

### 4. Kingbase 与 MySQL 脚本不完全一致

两种数据库在字段类型、自增主键、时间函数、部分语法上可能存在差异，因此需要分别维护 MySQL 和 Kingbase 版本脚本。实际运行时应选择与当前数据库环境对应的脚本。

## 九、总结

数据库模块是整个 AGV 智能巡检系统的基础支撑部分，为任务管理、缺陷识别、传感器数据、车辆状态、系统配置等功能提供数据存储能力。

通过分别提供 MySQL 和 Kingbase 脚本，系统能够适配不同数据库环境，便于课程实训、演示部署和后续扩展。
